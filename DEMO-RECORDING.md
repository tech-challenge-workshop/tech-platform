Technical steps only. Target 14 minutes.

## Setup, before recording

```sh
cd ~/Projects/FIAP/tech-challenge-org/tech-platform
export AWS_PROFILE=free-tier
export GATEWAY="http://$(kubectl get svc -n kong kong-gateway-proxy \
  -o jsonpath='{.status.loadBalancer.ingress[0].hostname}')"

./scripts/smoke-test.sh          # must end 23 passed, 0 failed
```

Postman: import `postman/tech-challenge.postman_collection.json`, set
`baseUrl` to `$GATEWAY` and `adminApiKey` from
`grep '^ADMIN_API_KEY=' k8s/.secrets.env | cut -d= -f2-`.

**Change the plate** in `2 · Catálogo → Criar veículo` — it is unique per
vehicle and the smoke test just used one.

Datadog: save two searches under APM → Traces.

| Name | Query |
| --- | --- |
| `Saga` | `env:production resource_name:"POST /work-orders"` |
| `Errors` | `env:production status:error` |

Both in the **Traces** view. Filtering on the entry resource is enough — health
probes are never the root span of a work order, so they drop out on their own.

Prepare a trivial commit but **do not push yet** — a comment or a version
string in `work-order-service`.

## 1:00 — Authentication

Postman, folder `1 · Autenticação`:

1. **Admin — obter token** → 200, token stored automatically
2. Decode the payload at [jwt.io](https://jwt.io) → point at `role: admin` and
   `iss: auth-service`
3. **Cliente — obter token por CPF** → 200

Point out: no password anywhere; the Lambda validates the document and calls
`/customers/lookup` before issuing.

---

## 2:00 — Security

Postman, folder `5 · Segurança`:

1. **Sem token → 401** — rejected by Kong, never reaches a pod. k9s logs nothing.
2. **Chave admin errada → 401**
3. **Rota pública sem token → 200** — `/parts/prices`, service-to-service

Leave `Admin tentando aprovar → 403` for the saga section, where the work order
exists.

---

## 3:00 — Catalogue

Postman, folder `2 · Catálogo`, run all five in order. Ids are captured
automatically.

Mention while running: the part goes to MongoDB Atlas, the customer to RDS —
different services, different databases.

---

## 4:00 — Saga, happy path

**Postman and k9s side by side, k9s showing the work-order-service log.**

1. `3 · Saga completa → Abrir OS` → 201

**Watch k9s.** Within ~2 seconds, with no further commands:

```
work_order.status_changed  RECEIVED
work_order.status_changed  IN_DIAGNOSIS
work_order.status_changed  AWAITING_APPROVAL
```

2. **Consultar OS** → `AWAITING_APPROVAL`
3. **Consultar orçamento** → generated by billing-service
4. **Consultar peça (reservada)** → `reservedQuantity` rose

5. `5 · Segurança → Admin tentando aprovar → 403` — valid token, wrong role
6. `3 · Saga → Aprovar orçamento (cliente)` → 201

k9s: `IN_EXECUTION`

7. **Registrar diagnóstico** — free-form document
8. **Iniciar reparo** → **Concluir reparo**

k9s: `FINISHED`

9. **Consultar OS (final)** → five transitions in history
10. **Consultar peça (consumida)** → `reservedQuantity` back to 0

---

## 7:00 — Compensation

Postman, folder `4 · Compensação`:

1. **Abrir segunda OS** → wait for `AWAITING_APPROVAL` in k9s
2. **Aprovar orçamento (cliente)** → wait for `IN_EXECUTION`
3. **Falhar reparo**

k9s: the saga unwinds — payment refunded, quote cancelled, parts released,
`CANCELLED`.

4. **Consultar OS (cancelada)**
5. **Consultar peça** → the reserved units are back

## 8:30 — Distributed trace

Browser, Datadog APM → Traces. **Make sure the `Traces` toggle is selected, not
`Spans`** — in Spans view each row is a single span; in Traces view each row is
one complete distributed transaction.

Saved search `Saga`. Open the most recent trace, tab **Flame Graph**.

Point at, in order:

1. **`% Exec Time` legend** — `work-order-service`, `billing-service`,
   `execution-service` in one trace
2. **The stacked bars** — each colour a different service
3. **`saga.*` spans** — custom instrumentation, from `TracingPort.withSpan()`
4. **`pg.query`** — click it, the SQL appears in the panel below
5. **`amqp.command`** — the RabbitMQ publish
6. Tab **Map** — the dependency graph

Then Dashboards → `Tech Challenge — Work Orders`: daily volume, average time per
status, cancellations.

## If something fails live

| Symptom | Action |
| --- | --- |
| Saga stops at `RECEIVED` | `kubectl logs -n tech-challenge deploy/execution-service --tail=20` |
| Postman 401 everywhere | the admin token expired — rerun `1 · Autenticação` |
| Vehicle returns a conflict | the plate is taken; change it |
| No trace in Datadog | takes ~1 min to index; keep going and come back |
| Pipeline still running at 10:30 | show the previous successful run instead |
